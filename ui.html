      1. Tổng Quan & Kiến Trúc Cốt Lõi

      v1.6.8 · Zero-Dependency · Multi-Protocol Edge Gateway

      LLM Switcher là cổng ngõ biên (Edge Gateway) và bộ điều phối chuyển đổi đa giao thức LLM siêu nhẹ, hoàn toàn Zero-Dependency (xây dựng 100% bằng thư viện chuẩn của Node.js: http, fs, os, path, crypto, fetch; không cần npm install, thời gian khởi động lạnh <50ms). Hệ thống đóng vai trò cầu nối thông minh và trong suốt giữa các AI Coding CLI hàng đầu (Claude Code, OpenAI Codex, Antigravity CLI agy) với mọi nhà cung cấp mô hình LLM (OpenAI-compatible, Anthropic Native, Vertex Native, Google Code Assist).

      Tại sao bạn cần LLM Switcher? Các proxy trung gian thông thường thường làm biến dạng giao thức phản hồi: làm mất khối suy luận thinking_delta, cắt vụn arguments của tool calls, làm lệch cache hoặc khiến Claude Code / Codex hiện banner cảnh báo "custom API endpoint". LLM Switcher chạy ngay trên máy cục bộ (127.0.0.1:3456 và :3457), thực hiện 100% Native Emulation và tự chữa lành (Self-Healing) payload mà tuyệt đối không sửa file cấu hình gốc của công cụ.

      4 Trụ Cột Đột Phá Của Hệ Thống

      • 100% Native Emulation: Chuyển đổi mọi phản hồi từ upstream thành luồng Anthropic SSE chuẩn (thinking_delta + tool_use) cho Claude Code, và Responses API events chuẩn cho Codex. CLI nhận được response native và hoàn toàn tin cậy server.
      • Zero Config Mutation: Tuyệt đối không đọc/ghi ~/.claude/settings.json hay ~/.codex/config.toml, và không ghi biến môi trường nào mà công cụ đọc như cấu hình. Không bao giờ xuất hiện banner cảnh báo "Custom API endpoint configured".
      • Cửa Sổ Context Theo Model Thực Tế: Tự động phát hiện cửa sổ ngữ cảnh chính thức từ upstream (ví dụ 1M tokens), truyền đúng max_context_window và context_window trong /v1/models để Codex tự tin lập kế hoạch và nén lịch sử chính xác. Claude Code tự ước lượng phiên theo model nó gọi.
      • Bifrost Passthrough: Khi bạn dùng tài khoản của chính nhà cung cấp đó trên pool của intact, request sẽ đi xuyên qua nguyên vẹn 100% byte-for-byte, bỏ qua bộ dịch giao thức và Healer, chỉ thay đổi API key an toàn.

      3. intact Gateway — Cài Đặt & Vận Hành Upstream Pooler (Khuyên Dùng)

      Recommended Companion · Multi-Account Pooler · Zero-CGO

      intact là cổng ủy quyền lưu trữ credential (Credential Proxy) và bộ điều phối pooling đa tài khoản LLM hiệu năng cao được xây dựng chuyên biệt để làm upstream cho LLM Switcher. Được viết bằng ngôn ngữ Go thuần (Single Static Binary, Zero-CGO với driver SQLite Pure-Go, nhúng toàn bộ Web UI quản trị), intact khởi động tức thì, tiêu tốn cực ít RAM (<30MB) và phục vụ toàn bộ các tài khoản của bạn sau một Base URL thống nhất /v1.

      Mối quan hệ cộng sinh hoàn hảo giữa LLM Switcher và intact:
      • LLM Switcher (Client Edge :3456 / :3457): Chạy trên từng máy dev, bóc tách TLS blindfold không cảnh báo, bảo vệ file cấu hình gốc (Zero-Mutation), tự động vá lỗi schema và cứu tool-result mồ côi bằng Healer Engine, duy trì thinking budget.
      • intact Gateway (Server Pooler :20142): Chạy trên máy chủ tập trung (hoặc localhost), lưu trữ tập trung và an toàn các API Key / OAuth Token nhạy cảm, cân bằng tải xoay vòng nhiều tài khoản (Round Robin / Fallback), xử lý 429 thông minh (429 Retry Shorter), gắn kết phiên (Conversation stickiness) tối ưu hóa Prompt Cache, tự động lọc lỗi bằng Blacklist và đối chiếu Contract Lab.

      2 Tính Năng Đột Phá Độc Quyền Khi Dùng Cặp Đôi Này

      • Bifrost Passthrough Tối Thượng: Khi một AI Coding CLI (Claude Code, OpenAI Codex, Antigravity CLI agy) gọi đến đúng tài khoản của chính nhà cung cấp đó trên pool intact, request sẽ đi xuyên qua nguyên vẹn 100% byte-for-byte.       • Chu Trình Tự Cải Thiện 2 Chiều (Two-Loop Self-Improvement):
        • Vòng 1 (intact sửa lỗi upstream từ chối): Tự động phát hiện lỗi 429 giả mạo từ upstream, sử dụng thuật toán chia đôi (binary search halving) system prompt để cô lập chính xác câu văn bị nhà cung cấp chặn (ví dụ các câu "You are Codex, an agent based on GPT-5" hay "You are a Claude agent..." bị Google Antigravity chặn bằng fake 429), rồi lưu thành bộ lọc blacklist trong cơ sở dữ liệu SQLite. Toàn bộ máy dev nhận bản vá tức thì mà không cần cập nhật gateway.
        • Vòng 2 (Switcher sửa lỗi converter làm mất): Khi bật Contract Lab, Switcher gửi các mẫu trao đổi đã che dữ liệu người dùng (giữ nguyên độ dài chuỗi và enum) lên intact. intact so khớp và ghi nhận từng field bị mất.       Sao Lưu & Nâng Cấp An Toàn (Database Integrity Guarantee)

      Vì SQLite sử dụng chế độ WAL (Write-Ahead Logging), tuyệt đối không dùng lệnh cp sao chép file trực tiếp vì có thể làm mất dữ liệu chưa kịp flush vào đĩa. Hãy dùng API Online Backup chuẩn:

      Terminal · SQLite Online Backup 
      install -d -m 0700 /opt/intact/backup
(umask 077 && sqlite3 /opt/intact/intact.db ".backup /opt/intact/backup/intact-$(date +%F-%H%M).db")

      Để nâng cấp: giữ lại file binary cũ intact.prev, tải bản mới thay thế và chạy sudo systemctl restart intact. Schema database sẽ tự động được nâng cấp tương thích ngược.

      Cẩm Nang Sử Dụng & Vận Hành intact Chi Tiết Nhất

      1. Xác Thực TOTP & Đăng Nhập Lần Đầu (Zero-Password):

        Chạy lệnh intact -db /opt/intact/intact.db -show-totp (hoặc kiểm tra log journalctl -u intact). Mở Google Authenticator, 1Password hoặc Aegis trên điện thoại, chọn "Enter a setup key", nhập tên intact và khóa bí mật in ra. Truy cập giao diện Web Dashboard và nhập mã 6 số để đăng nhập.

      2. Thêm Nhà Cung Cấp & Kết Nối (Providers & Connections):

        Vào mục Providers → Add trên thanh menu của intact:

        • API-Key Providers: Groq, OpenRouter, Vertex AI, NVIDIA NIM, DeepSeek, Cloudflare Workers AI... (chỉ cần dán API key).
        • Coding Tool OAuth Sign-ins (Class A): Claude Code, OpenAI Codex, Antigravity (Google), GitHub Copilot (đăng nhập bằng browser OAuth hoặc device-code).
        Lưu ý về Antigravity: Lần đăng nhập tài khoản Antigravity đầu tiên có thể mất khoảng 1 phút do intact tự động liên hệ Google để tải về OAuth client secret.
      3. Chiến Lược Điều Phối Tải & Xoay Vòng (Rotation & Failover):
        • Round Robin (1 req/turn): Chia đều tải qua từng request giữa các tài khoản đang hoạt động.
        • Round Robin (N reqs/turn): Phục vụ liên tục N request trên một tài khoản trước khi chuyển sang tài khoản kế tiếp. Đây là chế độ lý tưởng để giữ ấm Prompt Cache (Anthropic/OpenAI prompt cache hits), giúp tiết kiệm 50-90% chi phí và giảm độ trễ tối đa.
        • Fallback: Luôn ưu tiên tài khoản chính (Primary). Chỉ chuyển sang tài khoản dự phòng khi tài khoản chính gặp lỗi 429/500/503 hoặc cạn quota.
        • Standby Account: Đánh dấu tài khoản dự phòng ngủ đông, chỉ được kích hoạt khi toàn bộ tài khoản chính gặp sự cố.
        • Conversation Stickiness (Gắn kết phiên): intact tự động nhận diện phiên hội thoại theo Session ID (X-Claude-Code-Session-Id, session_id) và ghim hội thoại vào tài khoản phục vụ trước đó trong vòng 1 giờ để tối đa hoá cache.
        • 429 Retry Shorter Đột Phá: Khi một cuộc trò chuyện dài gặp lỗi rate limit 429 token-per-minute, intact tự động cắt ngắn lịch sử ngữ cảnh và gửi thử lại ngay lập tức trên tài khoản tiếp theo, bảo vệ phiên làm việc của bạn không bị crash giữa chừng.
      4. Tạo API Key Cho Client:

      5. Quy Tắc Định Tuyến Mô Hình (Model Routing Syntax):

      5. Blindfold Mode & Bảo Mật Chứng Chỉ CA

      Port :3457 · Zero-Warning Interceptor

      Trên Codex CLI, khi bạn ghi đè Base URL theo cách thông thường (--config openai_base_url=...), giao diện /model sẽ hiển thị một dòng cảnh báo phiền toái: "base URL is overridden to http://... Selecting models may not be supported or work properly.".

      Blindfold Mode giải quyết triệt để vấn đề này. Codex và Claude Code tiếp tục gửi request đến endpoint chính hãng, trong khi LLM Switcher đánh chặn ở tầng mạng thông qua proxy trung gian HTTPS_PROXY=http://127.0.0.1:3457. File cấu hình của tool hoàn toàn nguyên vẹn.

      Bảng Định Tuyến Cố Định Của Interceptor (:3457)

      Domain Đích (CONNECT Host) Đường Dẫn Bị Đánh Chặn (Về Gateway :3456) Đường Dẫn Còn Lại (Tunnel Ra Internet Thật)
      api.anthropic.com /v1/messages, /v1/messages/* Đăng nhập OAuth, telemetry, billing (giữ nguyên vẹn)
      api.openai.com /v1/responses, /v1/models Tài khoản, đăng nhập, thanh toán (giữ nguyên vẹn)
      chatgpt.com /backend-api/codex/* (được chuẩn hóa thành /v1) Mọi request web và session khác (giữ nguyên vẹn)
      Mọi domain khác (Google, GitHub, Web) Không chặn Tunnel thẳng ra Internet dạng raw TCP, không đọc dữ liệu
      Địa chỉ nội bộ (127.0.0.1, private IP) Bị từ chối (HTTP 403/421) Chống tấn công SSRF và lạm dụng mạng nội bộ

      🔒 Cam Kết An Toàn & Cô Lập Chứng Chỉ CA

      • Tự sinh 100% tại máy cục bộ: Cặp khóa ca.pem và ca.key được tự động tạo lần đầu bằng thư viện crypto chuẩn của Node.js. Private key được bảo vệ với quyền nghiêm ngặt 0600. Tuyệt đối không tải key từ Internet.
      • Không can thiệp vào Hệ Điều Hành: Tuyệt đối không cài chứng chỉ vào Windows Certificate Store, macOS Keychain hay Linux /etc/ssl/certs. Bạn không cần quyền root hay Administrator.
      • Chỉ tin cậy trong phạm vi tiến trình (Process-Scoped): Chứng chỉ chỉ được tiêm vào bộ nhớ RAM của claude (qua NODE_EXTRA_CA_CERTS) và codex (qua CODEX_CA_CERTIFICATE). Trình duyệt web và ứng dụng khác hoàn toàn không tin cậy chứng chỉ này.
      • Ràng buộc tên miền mật mã học (X.509 Name Constraints): CA được cấu hình bắt buộc chỉ cho phép ký duy nhất cho 3 domain: api.anthropic.com, api.openai.com, và chatgpt.com. Ngay cả khi lộ private key, mọi kết nối tới ngân hàng, Google, GitHub đều bị từ chối ngay lập tức.
      • Bảo toàn chứng chỉ VPN / Doanh nghiệp: Nếu máy bạn có sẵn CA công ty trong NODE_EXTRA_CA_CERTS, script ensure-ca-bundle.mjs sẽ tự động gộp cả 2 chứng chỉ vào một bundle tạm thời, không bao giờ làm đứt mạng nội bộ.
      • Lưu ý tạo chứng chỉ trên Windows: Chạy lệnh bash blindfold/make-certs.sh trong Git Bash. Tuyệt đối không dùng New-SelfSignedCertificate trong PowerShell vì lệnh này thiếu extendedKeyUsage serverAuth gây lỗi handshake.

Relay này bắt buộc Gateway phải cung cấp bằng chứng mã hóa dựa trên gateway.secret trước khi chuyển token. Nếu gateway chưa chứng minh được danh tính trong 3 giây, agy sẽ fallback về Google endpoint chính thức và token không bao giờ bị phát tán sang tiến trình lạ.

      7. Tối Ưu Token & Healer Engine

      Headroom · RTK · Ponytail Interoperability

      Các công cụ cắt tỉa prompt như Headroom, RTK (Rust Token Killer) và Ponytail cố gắng giảm input tokens bằng cách xóa bớt lịch sử hội thoại hoặc dòng lệnh. Tuy nhiên, hành động này thường phá vỡ đồ thị tin nhắn:

      • Orphaned tool_result: Optimizer xóa mất lượt assistant chứa tool_use nhưng lại giữ lại lượt user chứa tool_result $\implies$ Anthropic lập tức văng lỗi HTTP 400 (tool_use_id does not correspond to any tool_use).
      • Consecutive user turns: Xóa các lượt trung gian khiến 2 lượt user đứng liền nhau $\implies$ Vi phạm quy tắc luân phiên role của Anthropic gây crash HTTP 400.
      • Reasoning Suppression: Tự ý gọt bỏ tham số thinking hoặc budget để tiết kiệm token $\implies$ Khiến các model tư duy sâu (Opus, Gemini Flash) trở nên nông cạn, trả lời ngắn cũn và lỗi code.
      • Broken Schemas: Cắt cụt JSON hoặc trả schema rỗng {} làm Gemini/Vertex từ chối xử lý.

      Mô Hình Phân Tầng Bắt Buộc

      Kiến trúc tầng bảo vệ
      [CLI Agent] ──> [Optimizer Proxy: Headroom / RTK] ──> [LLM Switcher :3456] ──> [Internet / Upstream]
                                                      │
                                                      ├── 1. Tự chữa lành tool_result mồ côi thành text
                                                      ├── 2. Tự gộp các lượt cùng role liên tiếp
                                                      ├── 3. Tự phục hồi tham số suy luận thinking
                                                      ├── 4. Sửa schema rỗng {} cho Gemini/Vertex
                                                      └── 5. Giữ nguyên 100% tracing headers (x-rtk-*)

      8. Tích Hợp Agent Skill & MCP Server

      Control-Plane Security & Automation

      Để đảm bảo các AI Agent tự hành (Claude Code, Cursor, Opencode, Windsurf) không bao giờ tự ý sửa đổi file cấu hình hệ thống hoặc bypass Gateway, LLM Switcher cung cấp 2 tài nguyên chuẩn hóa:

      1. Agent Skill (skills/llm-switcher/SKILL.md)

      Tập luật bắt buộc dạy cho AI Agent:

      • Mọi request LLM và proxy nén token phải trỏ về http://127.0.0.1:3456.
      • Tuyệt đối không sửa ~/.claude/settings.json hay ~/.codex/config.toml.
      • Không bao giờ hướng dẫn sub-agent chạy source env.sh (đã có launcher shims tự tiêm).

      # Cài đặt cho Opencode:
cp -r skills/llm-switcher ~/.config/opencode/skills/

# Cài đặt cho Claude Code:
cp -r skills/llm-switcher ~/.claude/skills/

      2. MCP Server (mcp.mjs)

      Server đạt chuẩn Model Context Protocol hoạt động qua stdio JSON-RPC 2.0 (không cần dependencies). Thêm vào cấu hình MCP (ví dụ opencode.jsonc hoặc claude_desktop_config.json):

  "mcp": {
    "llm-switcher": {
      "type": "local",
      "command": ["node", "/path/to/llm-switcher/mcp.mjs"],
      "enabled": true
    }
  }
}

      9. Tính Năng Nâng Cao: Compaction, Goal Check & Contract Lab

      Pro Features · Cache & Quality Gate

      A. Idle Compaction (Nén Prefix Khi Nhàn Rỗi)

      Khi một phiên làm việc dừng lại quá lâu (>15 phút mặc định), prompt cache của các nhà cung cấp LLM (Anthropic: 5 phút, OpenAI: 30 phút, Gemini: 1 giờ) sẽ hết hạn (cold cache). Request tiếp theo sẽ phải thanh toán toàn bộ chi phí token input ban đầu mà không được hưởng giảm giá cache.

      Idle Compaction phát hiện thời gian nhàn rỗi và tự động nén gọn prefix lịch sử cũ, lưu cache xác thực trong STATE_DIR/idle-compact mà không chạm vào file JSONL của Claude hay SQLite của Codex.

      Terminal · Quản trị Compaction
      switch compact on                  # Kích hoạt nén cho Claude Code
switch compact codex on            # Kích hoạt nén cho Codex Responses
switch compact idle 20             # Đặt ngưỡng nhàn rỗi là 20 phút (1-1440)
switch compact min 128             # Ngưỡng kích thước tối thiểu 128 KB
switch compact model <model-id>    # Chỉ định model tóm tắt chạy ngầm
switch compact model none          # Tắt tóm tắt model, dùng cắt tỉa tất định
switch compact status              # Kiểm tra cấu hình hiện tại

      Cắt tỉa tất định (Deterministic Mode): Khi không đặt summary model, hệ thống giữ lại text đầu và gần nhất trong ngân sách (userChars: 3000), loại bỏ payload tool cũ nhưng bảo toàn nguyên vẹn các cặp tool call/result mới nhất (keepRecent: 6) mà không tốn bất kỳ token nào để gọi AI tóm tắt.

      B. Goal Check: Cơ Chế Veto Độc Lập Bằng Jev System One

      Trong Claude Code, khi dùng lệnh /goal, mô hình evaluator đọc transcript và có nguy cơ bị đánh lừa: coi việc sửa báo cáo (rút finding) là đã sửa code thật và vội vàng đánh dấu hoàn thành (False Completion).

      Goal Check chặn phản hồi của evaluator trước khi gửi về client, đồng thời gọi mô hình quyết định Jev (System One) chấm điểm trên 3 trục độc lập:

      • complete $\ge 0.90$: Công việc theo condition đã hoàn thành thực sự.
      • evidence $\ge 0.85$: Có tool-result trực tiếp chứng minh kết quả thực thi (chạy test, compile...).
      • unfinished $\le 0.10$: Không còn công việc dang dở hoặc lỗi chưa xử lý.
      Nguyên tắc Fail-Closed: Gateway chỉ trả về ok: true khi cả evaluator gốc lẫn Jev đồng thuận. Bất kỳ lỗi mạng, timeout hoặc thiếu evidence đều bị Veto (ok: false) để bảo vệ chất lượng công việc. Cấu hình tại tab Goal Check trên thanh điều hướng.

      C. Contract Lab: Tự Hoàn Thiện & Chống Rơi Rớt Dữ Liệu Với Intact

      Bộ đôi LLM Switcher và intact vận hành 2 vòng lặp tự sửa lỗi khép kín:

      • intact sửa lỗi nhà cung cấp từ chối: Thu thập lỗi 429 giả mạo, replay và bóc tách câu lệnh cấm (như fingerprint Codex/Claude) thành bộ lọc tự động phân phối cho mọi máy trạm.
      • Switcher sửa lỗi rơi rớt field qua chuyển đổi: Khi bật Contract Lab, Gateway gửi mẫu exchange được che giấu dữ liệu (masking: mọi text nhạy cảm đều biến thành chuỗi ký tự x cùng độ dài, chỉ giữ lại cấu trúc và enum) lên intact. intact so sánh và phát hiện field bị rơi rụng.
      Terminal · Lệnh Contract Lab
      switch contract-probe              # Gửi 6 test probe qua gateway lên intact
switch contract-check              # Lấy các trường bị mất và tạo file unit test tự động

      Giải Thích Các Tham Số Cấu Hình Quan Trọng

      • thinkingMode:
        • auto (mặc định cho intact, 9Router): Phục hồi thinking bị cắt, tự thêm chỉ dẫn <think> cho model thường, gửi cả thinking + reasoning_effort.
        • native (OpenAI chuẩn): Chỉ gửi reasoning_effort khi client yêu cầu, không sửa prompt, dùng max_completion_tokens.
        • off: Tắt hoàn toàn suy luận, không gửi tham số reasoning nào.
      • thinkingEffort: auto (client tự chọn) hoặc ghi đè cứng: none, minimal, low, medium, high, xhigh, max, ultra. Tự động quy đổi sang ngưỡng cao nhất mà provider đích hỗ trợ.

      11. Xử Lý Sự Cố & Câu Hỏi Thường Gặp (FAQ)

      Troubleshooting Playbook

      Q1: Lỗi EADDRINUSE: Cổng 3456 hoặc 3457 đã bị tiến trình khác chiếm dụng?

      Chạy lệnh switch doctor để phát hiện tiến trình đang giữ cổng. Bạn có thể đổi cổng gateway sang cổng khác bất kỳ bằng lệnh: switch port 8080 (gateway sẽ tự động cập nhật và khởi động lại). Nếu cổng Blindfold bị chiếm, đổi blindfold.port trong config.json.

      Q2: Claude Code hiển thị banner "Custom API endpoint configured"?

      Nguyên nhân do trước đây bạn đã cấu hình ANTHROPIC_BASE_URL trực tiếp vào ~/.claude/settings.json. Hãy chạy switch doctor: Switcher sẽ phát hiện và dọn sạch các trường thừa này để trả về trạng thái Zero-Mutation trong suốt.

      Q3: Lệnh claude --resume trong cửa sổ terminal mới không đi qua Gateway?

      Điều này xảy ra khi thư mục shims ~/.llm-switcher/bin chưa được đặt lên đầu biến PATH của bạn. Hãy kiểm tra bằng lệnh switch shim status và đảm bảo dòng export PATH="$HOME/.llm-switcher/bin:$PATH" có mặt trong ~/.bashrc hoặc ~/.zshrc và mở một terminal mới.

      Q4: Claude Code Remote Control (claude rc) có dùng được với Switcher không?

      Một phiên Remote Control chạy qua 2 hop:

      • Session bridge (api.anthropic.com/v1/code/sessions/*): Chạy trực tiếp qua Anthropic để đồng bộ phiên và kiểm tra gói Max/Pro.
      • Inference: Các cuộc gọi model của agent mới đi qua LLM Switcher.

      Lưu ý: Bạn cần duy trì tài khoản Claude còn quota cho hop bridge; nếu tài khoản hết quota, phiên sẽ bị ngắt ngay tại bridge trước khi request model kịp đến Gateway.

      Q5: Trên Windows, làm thế nào để tạo chứng chỉ cho Blindfold Mode?

      LLM Switcher tự động tạo chứng chỉ bằng Node.js crypto khi bạn kích hoạt tool. Nếu muốn tạo thủ công bằng OpenSSL, hãy chạy lệnh bash blindfold/make-certs.sh trong Git Bash (không chạy trong PowerShell vì lệnh New-SelfSignedCertificate thiếu thuộc tính serverAuth).

      Q6: Antigravity CLI báo lỗi 502 Bad Gateway khi gọi qua relay?

      Điều này xảy ra khi Gateway chưa khởi động hoặc phiên bản Gateway cũ hơn relay dẫn đến không vượt qua thử thách gateway.secret. Hãy chạy switch off rồi switch on để khởi động lại Gateway đồng bộ.

      Q7: Màn hình /model của Codex không hiển thị đúng model mong muốn?

      Đảm bảo profile phục vụ Codex có trường publicModels khai báo danh sách tên model chính thức (ví dụ ["gpt-5.6-sol", "gpt-5.6-terra", "gpt-5.6-luna"]) tương ứng với các slot main, review, subagent trong defaultModels.

      Q8: Làm thế nào để gỡ cài đặt sạch sẽ hoặc khôi phục hoàn toàn về mặc định?

      Terminal · Clean Uninstall
      switch off                     # Khôi phục endpoint chính hãng
switch shim uninstall          # Gỡ bỏ launcher shims
switch service uninstall       # Gỡ bỏ OS background service
switch plugin uninstall        # Gỡ bỏ các plugin hook thông báo
npm uninstall -g llm-switcher  # Gỡ bỏ package npm (nếu cài qua npm)
